Lab: Dependency Injection in Flutter

Case Study: Display Today's Timetable for a Student

Objective

  • Understand how Dependency Injection (DI) works.
  • Implement 4 types of DI.
  • Compare which DI approach is better for specific scenarios.

Case Study

Build a simple feature: "Display today's timetable for a student".

Common Setup

class TimetableService {
  List<String> getTodaySchedule() {
    return [
      "8:00 AM - Data Structures",
      "10:00 AM - Software Engineering",
      "2:00 PM - Mobile Programming"
    ];
  }
}

Task 1: Global DI

// Global instance
final timetableService = TimetableService();

class TimetableController {
  List<String> getSchedule() {
    return timetableService.getTodaySchedule();
  }
}

Task 2: Constructor DI

class TimetableController {
  final TimetableService service;

  TimetableController(this.service);

  List<String> getSchedule() {
    return service.getTodaySchedule();
  }
}

// Usage
final controller = TimetableController(TimetableService());

Task 3: InheritedWidget DI

class TimetableProvider extends InheritedWidget {
  final TimetableService service;

  const TimetableProvider({
    super.key,
    required this.service,
    required super.child,
  });

  static TimetableProvider of(BuildContext context) {
    final provider =
      context.dependOnInheritedWidgetOfExactType<TimetableProvider>();
    assert(provider != null, 'No TimetableProvider found in context');
    return provider!;
  }

  @override
  bool updateShouldNotify(TimetableProvider oldWidget) =>
      service != oldWidget.service;
}

// Access from widget tree
final service = TimetableProvider.of(context).service;

Task 4: Service Locator (GetIt)

final getIt = GetIt.instance;

void setup() {
  getIt.registerLazySingleton<TimetableService>(
    () => TimetableService(),
  );
}

class TimetableController {
  final TimetableService service = getIt<TimetableService>();

  List<String> getSchedule() {
    return service.getTodaySchedule();
  }
}

Comparison of DI Approaches

Approach Pros Cons
Global DI Simple and fast setup Tight coupling, hard to test
Constructor DI Best for testing and modular code More boilerplate in large projects
InheritedWidget DI Good integration with Flutter widget tree Can become verbose for complex dependency graphs
Service Locator (GetIt) Clean usage and scalable registration Dependencies become less explicit

Recommended default: Constructor DI for core business logic, optionally combined with GetIt for app-wide composition.
